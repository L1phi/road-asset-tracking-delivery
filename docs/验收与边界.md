# 验收清单与已知边界

## 已验证的历史事实

- 固定737B和MoCo权重哈希，冻结核心模块，不重新训练、不改阈值。
- 历史test121：588个GT，conf≥0.359、同类IoU≥0.5一对一匹配，Micro F1=86.11%、Macro F1=74.39%。该结果是静态检测，不是视频资产计数准确率。
- 历史29段短视频的H20/4090 D关联分组一致性核验通过；不是所有原始浮点数逐位一致。
- 新交付入口的静态检查与文件校验结果见validation.json；GPU端到端为待验收。

## 企业环境必须补验

1. 使用Python3.11和冻结torch/torchvision/CUDA组合，执行pip check、包校验和GPU可用性检查。
2. MoCo GPU推理检查：运行`runtime/check_moco_h20_20261009.py --model models/moco-v3-r50-1000ep.pth.tar --samples runtime/moco_real_samples_20261009.npz --device cuda:0 --out moco_readiness.json`。
3. 提供合法的1080p/10FPS AVI短片，用唯一入口正式跑完，核对每段轨迹JSON及错误日志；与原入口在同输入下对比检测与轨迹分组。
4. 用有全资产GT的新视频验收误检、漏检、串号、断轨、重复计数。不得只看轨迹总数。
5. 对企业实际时长和视频数测显存、内存、耗时。全局关联候选矩阵可能随检测数快速增大；本首版未验收长视频和多任务并发，不自动套用短片吞吐。
6. 复核许可证、数据权限、隐私、错误恢复、部署运维要求后，再决定是否上线。

## 不承诺

- 不支持CPU静默替代GPU，也不自动改帧率/分辨率。
- 不做跨视频道路库存去重；每视频每类别独立编号。
- 不把检测到的轨迹数当作已验收资产库存。
- 不包含已删除的范例可视化，不随交付混入研究原始数据。
- 不承诺所有类别都稳定；组合牌和相似资产仍可能误关联。
- 不以新包装替代一次真正的目标GPU端到端验收。
